# mumumu 仕様書

無音カメラアプリ **mumumu** の仕様をまとめたドキュメントです。

## 1. 概要

| 項目 | 内容 |
| --- | --- |
| アプリ名 | mumumu |
| 種別 | 無音（静音）カメラアプリ |
| 対応プラットフォーム | iOS / Android |
| 技術スタック | Flutter（必要箇所のみネイティブプラグインを自作） |
| ネットワーク | 不要（完全オフライン動作） |

### 1.1 コンセプト

シャッター音を鳴らさずに写真・動画を撮影できるカメラアプリ。図書館や病院、寝ている子ども・ペットの撮影、
会議資料の記録など、静粛性が求められる場面での利用を想定する。起動が速く、すぐ撮れるシンプルな UI を最優先とする。

### 1.2 利用上の注意（悪用防止）

盗撮など違法・迷惑行為への利用を禁止する旨を、初回起動時のオンボーディングと利用規約に明記する。
撮影対象のプライバシーを尊重するよう注意喚起を表示する。

## 2. 法令・ストア審査上の前提

無音化はプラットフォームの制約が大きく、本アプリの成否を左右する最重要事項である。

### 2.1 iOS

- 日本・韓国向けに販売された端末では、`AVCapturePhotoOutput` による撮影時に OS がシャッター音を強制的に鳴らす。
  この音をアプリ側から抑止する実装は App Store Review Guidelines 上も認められない。
- 現実的な方式として、**キャプチャセッションのビデオフレームから静止画を切り出す**方法を採用する。
  この方式は無音だが、写真モードに比べ解像度・画質が劣る点をアプリ内で明示する。
- ストア掲載時、「無音」を前面に出した訴求はリジェクトの可能性があるため、
  アプリ名・説明文は「静かに撮れるカメラ」等の表現を用いる。

### 2.2 Android

- 端末・地域により `MediaActionSound` の抑止可否が異なり、日本向け端末ではシステム強制の場合がある。
- iOS と同様、`ImageReader` / プレビューフレームからのキャプチャ方式を併用する。

### 2.3 端末互換性

無音化の可否は端末依存であるため、検証済み端末の互換性一覧を管理し、
無音化できない端末では起動時にその旨をアプリ内で明示する。

## 3. 対応環境

- iOS 16 以上
- Android 10（API 29）以上
- 端末: スマートフォン（縦向き主体、横向きにも対応）。タブレットは best-effort。

## 4. 技術方針（Flutter）

- UI・アプリケーションロジックは Flutter / Dart で実装し、単一コードベースを維持する。
- カメラ制御は原則 `camera` パッケージを利用する。
- 無音キャプチャは `camera` パッケージだけでは実現できないため、
  **Platform Channel 経由の自作プラグイン**で以下をネイティブ実装する。
  - iOS: AVFoundation（`AVCaptureVideoDataOutput` からのフレーム取得と静止画化）
  - Android: CameraX / Camera2（`ImageReader` からのフレーム取得と静止画化）
- 保存処理もプラットフォーム API に依存するため、同プラグイン内で扱う。

### 4.1 プロジェクト構成（想定）

```
mumumu/
├── lib/
│   ├── main.dart
│   ├── app/            # アプリ全体の設定・ルーティング・テーマ
│   ├── features/
│   │   ├── camera/     # カメラ画面
│   │   ├── viewer/     # ビューア画面
│   │   ├── settings/   # 設定画面
│   │   └── onboarding/ # オンボーディング
│   ├── core/           # 共通ユーティリティ、権限、ロギング
│   └── platform/       # Platform Channel ラッパー
├── ios/
├── android/
├── packages/
│   └── silent_camera/  # 無音キャプチャ用の自作プラグイン
├── test/               # ユニット / ウィジェットテスト
├── integration_test/   # 結合テスト
```

### 4.2 状態管理・依存

- 状態管理: Riverpod を想定（軽量かつテスト容易性が高いため）。
- 永続化: `shared_preferences`（設定値のみ）。画像はアプリ内に保持しない。
- Lint: `flutter_lints` を採用し、CI で `flutter analyze` / `flutter test` を実行する。

## 5. 機能仕様

### 5.1 必須機能（MVP）

| 機能 | 内容 |
| --- | --- |
| 静音撮影（静止画） | シャッター音なしで撮影。ビデオフレーム切り出し方式を基本とする |
| カメラ切替 | 前面 / 背面カメラのトグル |
| ズーム | ピンチ操作、および倍率ボタン（端末対応レンズに応じて 0.5x / 1x / 2x など） |
| フォーカス / 露出 | タップでフォーカス＋露出、長押しで AE/AF ロック、露出補正スライダー |
| フラッシュ | OFF / ON / AUTO / トーチ |
| 保存 | 端末フォトライブラリへ保存。アプリ専用フォルダ `mumumu` に整理 |
| サムネイル | 直近の撮影結果をサムネイル表示、タップでビューアへ |
| グリッド表示 | 3 分割グリッドの ON / OFF |
| 権限フロー | カメラ / 写真ライブラリ / （動画時）マイクの権限リクエストと拒否時の説明 |

### 5.2 追加機能（フェーズ 2 以降）

- 静音での動画撮影（録画開始・終了音の抑止）
- 連写（バーストモード）
- セルフタイマー（3s / 5s / 10s）
- 音量ボタンでのシャッター、画面全体タップでのシャッター
- 解像度・アスペクト比選択（4:3 / 16:9 / 1:1）
- 画質設定（JPEG 品質、HEIC / JPEG 選択）
- 位置情報を Exif に付与する ON / OFF
- 前面カメラのミラー保存

いわゆる「ステルスモード」（画面を暗転させたまま撮影する機能）は、悪用リスクが高いため**搭載しない**。

### 5.3 非機能要件

- 起動から撮影可能までの時間: 1.5 秒以内
- シャッターレイテンシ: 300ms 以内
- 撮影時のメモリ使用量: 200MB 以内、連続撮影時のクラッシュゼロ
- オフライン完全動作（ネットワーク権限を要求しない）
- アナリティクス / クラッシュレポートを導入する場合は、匿名かつオプトインとする

## 6. 画面仕様

1. **オンボーディング**
   - アプリの用途説明、法令遵守の注意喚起、権限の用途説明 → 権限リクエスト
2. **カメラ画面（メイン）**
   - 上部バー: フラッシュ、グリッド、タイマー、設定
   - 中央: ライブプレビュー（アスペクト比に応じたレターボックス）
   - 下部バー: 直近サムネイル / シャッターボタン / カメラ切替
   - 右側: ズームスライダー、露出補正スライダー
3. **ビューア画面**
   - 撮影画像の確認、共有、削除、システムギャラリーで開く
4. **設定画面**
   - 保存形式、解像度、位置情報、シャッター操作方法、テーマ、
     利用規約 / プライバシーポリシー、OSS ライセンス表示

## 7. データ / 保存仕様

- 保存先
  - iOS: PHPhotoLibrary（`mumumu` アルバムを作成）
  - Android: MediaStore（`Pictures/mumumu`）
- ファイル名: `IMG_yyyyMMdd_HHmmss[_n].jpg`
- Exif: 撮影日時、機種、向きを付与。位置情報は設定に従う
- アプリ内に画像を隠し持たない（保存はシステムギャラリー基準）

## 8. プライバシーポリシー方針

- 撮影した画像・動画を端末外へ一切送信しない
- 個人情報を収集しない
- 各権限の用途をアプリ内およびストア掲載情報で明示する

## 9. 収益モデル

- 無料 + 広告を基本とする。ただしカメラ画面には広告を表示せず、ビューア / 設定画面のみに配置する。
- 買い切りの課金で広告除去および追加機能（連写、動画、フル解像度）を解放する。

## 10. リスクと対策

| リスク | 影響 | 対策 |
| --- | --- | --- |
| 「無音」を理由にストア審査で却下される | 公開不可 | 訴求を「静かに撮れるカメラ」とし、集中を妨げない点を前面に出す |
| 端末により無音化できない | 主要機能が成立しない | 端末ごとの互換性一覧を整備し、非対応時はアプリ内で明示 |
| フレーム切り出しによる画質低下 | 品質面の不満 | 端末が対応する最大解像度のビデオフォーマットを選択し、設定で写真モードへの切替も提供 |
| 悪用（盗撮など） | 社会的・法的リスク | 利用規約、初回警告を用意し、ステルス機能は非搭載とする |

4. **フェーズ 3**
